## 2. Insurance

**Categories the current business model needs investigated, based on what the venture actually does (not assumed beyond repository evidence):**

- **Public liability:** required, the venue receives members of the public daily; existing estimate basis A$20M cover (`docs/financial-setup.md` Step 8).
- **Professional indemnity:** required for the clinical (phlebotomy) and beauty/massage advisory components; existing estimate basis A$5M cover.
- **Clinical/medical malpractice-adjacent liability:** worth specific broker assessment given on-site blood collection, even though WDP holds the primary pathology accreditation; not resolved as a distinct policy line in this repository, a genuine question for the broker, not assumed either way.
- **Workers' compensation:** mandatory in WA for any employee; required regardless of headcount.
- **Business interruption:** relevant given the venue's single-location, single-revenue-stream model; existing estimate basis included in the A$975-1,583/month itemised range.
- **Contents/equipment insurance:** relevant given the capital equipment value in the procurement register (centrifuge, phlebotomy chairs, salon equipment); a genuine broker-assessment item, not yet separately quoted.
- **Product liability (retail/Cafe):** relevant if retail products or Cafe food/drink are sold; the current Cafe model (externally-supplied, warmed/toasted only) shifts primary food-safety liability toward the supplier, but GTT Center Perth's own handling/service still needs broker confirmation.
- **Cyber/data liability:** relevant given client health/booking data is held (Fresha, patient intake forms, 7-year clinical record retention); not currently itemised anywhere in this repository as its own policy line, a genuine gap worth raising with the broker.

**What the broker needs from us:** business activity description (clinical/wellness hybrid, explicitly disclosed up front per `docs/insurance-broker-quote-request-draft.md`'s own existing reasoning), employee count (approximately 10-12), premises description (once venue confirmed), equipment value (from the procurement register once quotes exist), public liability/professional indemnity coverage minimums already modelled (A$20M/A$5M), and clinical/beauty/massage/food-service activity disclosure in full, not a softened description.

**The exact broker package to send already exists:** `docs/insurance-broker-quote-request-draft.md`, status Not Sent, built entirely from `docs/financial-setup.md` Step 8 and `docs/external-resources-and-advisors.md` §4. This document was checked this round and found complete against every category above except cyber/data liability, which is not currently addressed in it. **Recommendation: add one line to the existing draft raising cyber/data liability, rather than creating a new document.** No broker has been contacted, per standing instruction not to contact anyone without explicit authorisation.

**Financial-model flag, restated for this task specifically:** the current financial model uses a ~A$400/month insurance placeholder against a real itemised estimate of A$975-1,583/month (`docs/CURRENT-STATE.md` line 214, already flagged there as `[PLACEHOLDER]`). This is not a new finding; it is confirmed current and restated here as the single most consequential financial-model input still requiring replacement with a real broker quote before any final opening/investment decision.

## 3. Employment Readiness

**What already exists:** staff position register, staffing pools, staffing solver, individual staff profiles (`docs/architecture/STAFF-PROFILES-COMPLETE.md`), wage assumptions, superannuation rate (12% SG, confirmed current for FY2026-27), a ready-to-use Fair Work Infoline script for the MA000027 Saturday-hours question, 4 job postings (phlebotomist, PM casual, receptionist, Venue Manager), and a staff onboarding schedule (`docs/onboarding.md` Parts A1-A4).

**What is genuinely missing:**

- **Employment contract template.** Does not exist anywhere in this repository. Should be drafted with solicitor/employment-specialist review given 2 different awards apply (MA000005 for treatment staff, MA000027 for phlebotomists) and the venue's clinical/wellness hybrid nature is not a standard single-award business.
- **Award classification confirmation.** MA000005 penalty rates disagree three ways across existing documents (Saturday 133% vs 150%, Sunday 200% vs 175%, Public Holiday 250% vs 250-275%), none independently verified against Fair Work's own published rates. This must be resolved (a direct Fair Work website/Infoline check) before wage costs in the financial model can be called confirmed rather than a researched assumption.
- **MA000027 Saturday ordinary-hours carve-out.** Script is ready (`docs/fairwork-infoline-query-script.md`), the call has not been made. This is upside-only risk (would only reduce modelled Saturday phlebotomist cost if the carve-out is real), not a blocker, but should still be closed before finalising contracts.
- **Right-to-work verification process.** Not documented; a standard employer obligation (visa/work-rights check), genuinely missing as a written process, not just a compliance fact everyone already knows.
- **Mandatory training records system.** First aid/CPR (HLTAID011 or equivalent) requirement is established in `docs/architecture/STAFF-PROFILES-COMPLETE.md`, but no system exists yet to track certification expiry/renewal across staff.
- **Incident reporting process.** The Emergency Response Plan covers the physical response; a separate written incident-reporting/record-keeping process (who logs it, where, retention) does not yet exist as its own document.
- **Probation/performance management policy.** Not documented.

**What is not a gap:** payroll setup, superannuation rate, rostering (Fresha-based, already modelled), leave entitlements (standard NES, no venture-specific complexity beyond the standard casual/permanent mix already modelled).

## 6. Commercial Launch Readiness

**Referral pathway (researched, not assumed, per `docs/architecture/MARKET-RESEARCH-BIRTHS-GDM-REFERRAL-2026.md`):** a valid pathology request form from a GP, obstetrician, or midwife is the standard requirement; the Australian pathology industry norm is that a provider accepts a valid request form regardless of whose letterhead it carries, meaning a client referred by their own GP or midwife does not need a WDP-specific form to be collected at this venue. **The one genuine remaining gap:** whether WDP's own venue-based Licensed Collection Centre model has any site-specific intake requirement beyond the industry-standard process; not found in any WDP correspondence, to be confirmed directly with Carole Rivers as part of operational handover, not before.

**Referral outreach itself:** genuinely not yet begun. The market research answers "how does a referral work"; it does not itself build GP/midwife/obstetrician relationships. This is real, actionable, and can start before the venue exists (introducing the venue concept to local GP clinics and midwife practices does not require a physical address).

**Prior-GDM market (researched, per the same document):** 18% current GDM diagnosis rate nationally, 30-41% recurrence rate in subsequent pregnancies. This supports a real, elevated-probability repeat-engagement segment, not a specific customer-count forecast (which would require the venture's own booking data over time). **What is missing is the execution side:** no retention/referral process exists yet to actually capture prior-GDM clients as repeat customers (e.g. a structured way to invite a GDM-positive client back, beyond the already-modelled "welcome GDM-positive clients back for a dedicated session" concept in the now-superseded-in-part `docs/extended-wellness-services.md`). This is a revenue-upside build, not an opening blocker.

**Website, booking system, Google Business Profile, social media, verified against the repository directly (2026-08-24), not assumed:** website is spec-only (`docs/website-spec.md`), no developer engaged, no domain registered anywhere in this repository. Fresha is selected and modelled but no live account exists yet (nothing to configure without confirmed staff/venue). Google Business Profile is explicitly plan-only, correctly stated as venue-address-dependent.
