## 1. What it is

Each test day has a secure record (a locked folder in the clinical system, one per date). Every referral or request copy is filed to the record of the TEST date, not the consult date. Real record: the booking and clinical system. No paper copy is made. Product name, hosting country and cost: NOT IN REPO.

## 2. Who files and when

| Step | Who | When | What |
|---|---|---|---|
| 1 | Midwife | End of each consult (Path B) | Writes the request in the system, marks "request issued". The system files a copy to the test-day record, named by booking reference number, not by name. |
| 2 | Client (Path A, optional) | At booking | Uploads a photo of her own referral. It lands in the test-day record marked "client upload, not yet checked". |
| 3 | Phlebotomist | Test morning, at the door check | Sees the original or the upload, ticks "outside request checked". Cannot edit it. |
| 4 | System | Evening after the test day | Locks the day record. A no-show or rebooked client's copy moves to her new test date. |

## 3. How staff find it on test morning

The phlebotomists open "Today" on a tablet or computer in the collection room. It lists the 18 clients by time with a flag: request issued, outside request checked, or missing. Tap a name to see the request. Missing flag: no draw until it is resolved (R). Phlebotomist start time before 06:50: NOT IN REPO. The venue manager sees the flag only (green, red), not the request.

## 6. If the internet is down (only if Anthony agrees)

| Part | Draft |
|---|---|
| Printed list | At 18:00 each evening the system prints tomorrow's list: time, booking reference number, first name, flag. No diagnosis, no request copy, no due date. |
| Where it is kept | Locked drawer in the collection room. Key: midwife on duty and one phlebotomist. Not at reception. |
| Shredding | Cross-cut shred after the test day. A one-line destruction log is signed. |
| On the day | If the system is down, phlebotomists use the printed list and the client's own original request. No request in her hands and none in the list, no draw. Nobody rewrites a request. |
| Midwife | Writes any new request on the pad of requests the lab provides (NOT IN REPO) and the system is updated when it returns. |
| If Anthony says no | The same day-of steps run from the original in the client's hand and a phone call to the midwife. The risk is more rebooked clients. |

Printed lists are a small paper risk again. They hold less than the old folder (no request copies, no notes) and cover one day, not 108 clients. Equipment (printer, lockable drawer): NOT IN REPO.
